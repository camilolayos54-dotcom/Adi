### 2. Guía de Estilo y Reglas de Calidad de Código

| Componente / Capa | Estándar de Código | Linter / Formateador | Regla Inviolable |
| --- | --- | --- | --- |
| **Backend (API)** | TypeScript / Modern JavaScript / Clean Code | ESLint + Prettier / Flake8 | Tipado explícito de modelos relacionales (Brand, SKU, Variant, Stock, Receipt). Cero `any` implícitos. |
| **Frontend (UI)** | Componentes modulares limpios | ESLint (React/Vue/JS) | Componentes de UI desacoplados de la lógica de peticiones HTTP (separar `services` de `components`). |
| **Base de Datos** | Nombres relacionales claros | Migration Scripts | Nombres de tablas en plural (`brands`, `products`, `variants`, `inventory_logs`, `receipts`) en snake_case. |
| **Manejo de Errores** | Try-Catch explícito | Middleware centralizado de errores | JAMÁS tragar excepciones. Devolver respuestas HTTP estructuradas (`{ success: false, error: string }`). |

### 3. Principios de Arquitectura Aceptados
- **KISS (Keep It Simple, Stupid):** Sin sobreingeniería de microservicios. Monolito desacoplado (Backend API + Frontend Web).
- **DRY (Don't Repeat Yourself):** Reutilización de servicios de validación de calzado y formateo de colillas.
