# 5. Estrategia de Ramificación (Branching Strategy)

### 1. Metadatos del Documento
**Proyecto:** Adi  
**Fase:** 2 — Project Kickoff  
**Entregable:** 5 de 13  
**Estado:** Aprobado  

### 2. Modelo de Ramificación (Gitflow Simplificado)

| Rama | Propósito | Nivel de Estabilidad | Regla de Mezcla (Merge) |
| --- | --- | --- | --- |
| `main` | Código de Producción desplegable (`v0.1.0-alpha`) | Altamente Estable | Solo mediante Pull Request aprobado con pruebas pasadas. |
| `develop` | Rama de integración continua de funcionalidades | Estable | Base para desarrollo de características. |
| `feature/*` | Desarrollo de nuevas características (Ej. `feature/bulk-import`) | En Desarrollo | Pull Request hacia `develop`. |
| `hotfix/*` | Correcciones críticas urgentes en Producción | Parche URG | Pull Request directo hacia `main` y `develop`. |

### 3. Convención de Mensajes de Commit (Conventional Commits)
- `feat(inventory): añadir modelo de tipo de par y variantes por talla`
- `fix(receipts): corregir formato de numeración en colillas de pago`
- `docs(kickoff): añadir entregable 05 de branching strategy`
- `refactor(backend): optimizar bulk insert en carga por lotes`

### 4. Políticas de Pull Request
- Requisito de compilación limpia y paso de pruebas unitarias al 100%.
- Aprobación mínima del Tech Lead antes de fusionar a `main`.
