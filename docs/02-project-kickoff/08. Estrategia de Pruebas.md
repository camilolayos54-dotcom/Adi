# 8. Estrategia de Pruebas

### 1. Metadatos del Documento
**Proyecto:** Adi  
**Fase:** 2 — Project Kickoff  
**Entregable:** 8 de 13  
**Estado:** Aprobado  

### 2. Pirámide de Pruebas y Cobertura Requerida

| Nivel de Prueba | Alcance y Módulos a Evaluar | Herramienta | Cobertura Mínima |
| --- | --- | --- | --- |
| **Pruebas Unitarias** | Lógica de cálculo de existencias, validación de SKUs, reglas de variante (color/talla/tipo de par) y numeración de colillas | Jest / Vitest / PyTest | > 80% de lógica de negocio |
| **Pruebas de Integración** | Endpoints HTTP de API Backend (CRUD de Catálogo, Bulk Ingest de Lotes y Transacciones de Stock) | Supertest / Postman Automated | 100% de los endpoints críticos |
| **Pruebas de Carga y Concurrencia** | Actualización simultánea de existencias y búsqueda masiva de marcas/modelos | K6 / Artillery | Concurrencia de 50 peticiones simultáneas con latencia < 100 ms |
| **Pruebas de Aceptación (UAT)** | Flujo completo de carga por lote y emisión de colillas por el Operador de Adi | Manual / Playwright | 100% de aprobación por el Operador |

### 3. Criterios de Bloqueo de Despliegue
Cualquier fallo en pruebas unitarias o de integración detiene el pipeline de integración continua (CI) e impide el merge a `main`.
