# 4. Clasificación del Problema

### 1. Metadatos del Documento

**Estado:** Aprobado  

### 2. Clasificación Arquitectónica
- **Arquetipo Dominante:** **Ineficiencia de Flujo de Trabajo (Workflow Inefficiency)**.
- **Por qué aplica:** El dolor principal reside en los procesos manuales y artesanales para clasificar y organizar el inventario de calzado (cargar foto por foto, asociar códigos a carpetas, controlar existencias de tallas y colores en tablas de Excel).
- **Por qué NO aplican los demás:** No es *Asimetría de Información* pura (los datos existen pero moverlos es manual), no requiere *Algorithmic Complexity* (no hay IA/modelos predictivos) ni *Integration Disconnect* (no hay sistemas legacy a integrar).

### 3. Remedio Estructural Sugerido
- **Design Pattern Genérico:** Single Source of Truth Inventory Engine (Gestor de Inventario Centralizado con esquema relacional explícito para calzado: Marca -> Modelo -> Código SKU -> Variante de Talla/Color/Tipo de Par -> Stock -> Costos y Colillas).
- **Foco Técnico (Para Ingeniería):** Diseñar un motor de backend y panel administrativo (CRM/Gestor) con alta eficiencia en operaciones CRUD de inventario, carga de lotes de productos y control relacional de existencias.
